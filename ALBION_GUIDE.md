## 1. Установка и запуск

### Требования
- Python 3.11+
- Telegram-бот (создать у [@BotFather](https://t.me/BotFather))
- (Опционально) MeritHub API credentials

### Установка
```bash
git clone <repo> && cd albion-mvp
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### Конфигурация (.env)
```dotenv
# === ОБЯЗАТЕЛЬНЫЕ ===
TELEGRAM_BOT_TOKEN=123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11

# Ваш TG ID (узнать: написать боту /whoami). Через запятую если несколько админов.
ALBION_ADMIN_TELEGRAM_IDS=111222333

# === ТАЙМИНГИ (для демо — уменьшаем) ===
ALBION_NOTIFY_PARENT_DELAY_MIN=1      # Через сколько мин уведомить родителя о неявке
ALBION_ESCALATE_DELAY_MIN=2           # Через сколько мин эскалация координатору
ALBION_SCHEDULER_INTERVAL_SEC=5       # Частота тика планировщика
ALBION_PRELESSON_REMINDER_MIN=15      # За сколько мин напоминание до урока
ALBION_CLASS_LIVE_GRACE_MIN=5         # Через сколько мин после старта проверять live

# === AI (опционально, без ключа — mock-режим) ===
OPENROUTER_API_KEY=sk-or-...

# === MERITHUB (опционально, без credentials — mock) ===
MERITHUB_CLIENT_ID=...
MERITHUB_CLIENT_SECRET=...
MERITHUB_WEBHOOK_SECRET=...

# === DEMO MODE ===
ALBION_DEMO_MODE=false                # true = включить mock-демо сценарии
```

### Запуск
```bash
# Локально (polling)
python -m src.main

# С вебхуками MeritHub (отдельный терминал)
uvicorn src.api.webhook:app --host 0.0.0.0 --port 8000
cloudflared tunnel --url http://localhost:8000  # или ngrok http 8000
```

## 2. Роли и регистрация

### Как регистрируются пользователи

**Автоматическая регистрация через /start:**

1. Пользователь открывает бота и нажимает `/start`
2. Бот показывает 3 кнопки:
   - 👨‍👩‍👦 Я родитель
   - 🧑‍🏫 Я репетитор
   - 👨‍💼 Я координатор
3. Пользователь нажимает нужную кнопку → регистрация завершена
4. Бот показывает профиль: роль, TG ID, имя

**Повторный /start** показывает профиль и кнопку «🔄 Сменить роль».

### Ручное назначение ролей (админом)

```
/whoami                        → узнать свой TG ID
/role 123456789 tutor          → назначить роль репетитора
/role @username parent         → назначить роль по username
/roles                         → список всех участников и ролей
```

### Роли в системе

| Роль | Эмодзи | Что делает |
|------|--------|-----------|
| `parent` | 👨‍👩‍👦 | Получает уведомления о неявке, pre-lesson напоминания |
| `tutor` | 🧑‍🏫 | Отмечает неявку, получает pre-lesson напоминания, подтверждает старт |
| `coordinator` | 👨‍💼 | Получает эскалации, outcome-уведомления, алерты |
| `student` | 🎓 | Зарезервирована (ученики живут в MeritHub) |

### Привязка TG к ученикам MeritHub

Ученики в MeritHub привязываются к TG **родителя** (не к самому ученику):

```
/mh_user s01 333333333 Алиса Джонс
                ↑
         TG ID родителя
```

Когда система обнаруживает неявку ученика `s01` → уведомление уходит на TG `333333333`.

## 3. Настройка учеников, репетиторов и родителей

### Быстрый способ: /seed10

Одной командой создаёт 10 тестовых учеников + 3 репетиторов:

```
/seed10 333333333 444444444
```

- `s01`–`s05` → привязаны к родителю `333333333`
- `s06`–`s10` → привязаны к родителю `444444444`
- Если один TG → все 10 к нему

Создаёт:
- 3 репетитора: `t01` (Анна, English), `t02` (Иван, Math), `t03` (Мария, Chemistry)
- 10 учеников с предметами

### Ручное создание

```bash
# Ученик (базовый)
/mh_user <clientUserId> <parentTG> <Имя>
# Пример:
/mh_user s01 333333333 Алиса Джонс

# Ученик с контактами родителя (email и/или телефон)
/mh_user s01 333333333 Алиса email=parent@example.com
/mh_user s01 333333333 Алиса phone=+447493994501
/mh_user s01 333333333 Алиса email=parent@ex.com phone=+447493994501

# Репетитор (без TG)
/mh_tutor t01 Анна Петрова

# Репетитор с TG (для pre-lesson напоминаний!)
/mh_tutor t01 555555555 Анна Петрова

# Проверка
/mh_students     → список учеников + контакты родителей
/mh_contacts     → все контакты
```

> **Примечание:** В MeritHub нет полноценных карточек родителей (только email во вкладке Parents/Clients).
> ALBION хранит все контакты родителя (TG, phone, email) в своей БД, привязывая их к ученику.

### Регистрация родителей

Родители регистрируются автоматически при `/mh_user`:
- Если TG `333333333` ещё не в системе → создаётся как `parent`
- Если уже есть → роль не меняется

Можно вручную:
```
/role 333333333 parent
```

## 4. Создание занятий

### /mh_schedule — создать занятие + зачислить учеников

```
/mh_schedule <tutorCuid> <startRFC3339> <durationMin> <studentCuid...>
```

**Пример:**
```
/mh_schedule t02 2026-07-28T15:00:00+03:00 60 s01 s02 s04
```

Что происходит:
1. Создаётся класс в MeritHub (если подключён)
2. Зачисляются tutor и ученики
3. **Автоматически** планируются:
   - Pre-lesson reminder для parent (за T-15min)
   - Pre-lesson reminder для tutor (за T-15min)
   - Tutor start check (в момент T)
   - Class live check (T+5min)

### /mh_enroll — зачислить в существующий класс

```
/mh_enroll <classId> <studentCuid1> [studentCuid2 ...]
```

## 5. Сценарий неявки (главный флоу)

### Как запускается

**3 источника:**

| Источник | Как | Когда |
|----------|-----|-------|
| Ручной | `/pilot_absent` или `/absent <ID>` | Для демо / тестирования |
| Tutor start check | Кнопка «👤 Ученик не пришёл» | В момент начала урока |
| MeritHub webhook | `requestType=attendance` | После окончания урока |

### Полный флоу

```
1. Неявка зафиксирована
   ↓
2. Через ALBION_NOTIFY_PARENT_DELAY_MIN (1 мин в демо):
   Parent получает сообщение с 3 кнопками:
   ┌──────────────────────────────────────────┐
   │ 👋 Здравствуйте!                          │
   │                                           │
   │ Алиса отсутствовала на занятии (ID: C9). │
   │ Подскажите, что верно:                    │
   │ • всё в порядке                           │
   │ • сегодня занятия не будет                │
   │ • ученик опоздает                         │
   │                                           │
   │ [✅ Всё в порядке]                        │
   │ [❌ Сегодня не будет]                     │
   │ [⏰ Опоздаем]                             │
   └──────────────────────────────────────────┘

3. Вариант А: Parent нажимает кнопку
   → Инцидент закрыт
   → Coordinator получает outcome-уведомление
   → Эскалация отменена

4. Вариант Б: Parent пишет текстом ("опоздаем на 10 минут")
   → AI интерпретирует → "late"
   → Инцидент закрыт
   → Coordinator уведомлён с исходным текстом

5. Вариант В: Parent молчит ALBION_ESCALATE_DELAY_MIN (2 мин в демо)
   → Coordinator получает: 🚨 Эскалация: инцидент #N
   → Coordinator разбирает вручную

6. Если Parent ответил ПОСЛЕ эскалации:
   → Инцидент: escalated → resolved
   → Parent видит: "ℹ️ Координатор уже был уведомлён, но ваш ответ передан"
   → Coordinator получает поздний ответ
```

### /ok — запасной способ закрыть инцидент

```
/ok 5      → закрыть инцидент #5
```

## 6. Pre-lesson напоминания

### Parent reminder (за 15 мин до урока)

```
⏰ Напоминание: через 15 мин занятие.
Ученик: Алиса Джонс
Репетитор: Иван Сидоров

Подтвердите, пожалуйста, статус или ответьте текстом.

[✅ Будем] [⏰ Опоздаем] [❌ Не придём]
```

### Tutor reminder (за 15 мин до урока)

```
🧑‍🏫 Через 15 мин урок.
Репетитор: Иван Сидоров
Ученики: Алиса Джонс, Бен Смит

Подтвердите готовность.

[✅ Готов(а)] [⏰ Опоздаю] [❌ Не смогу] [🛠 Проблема]
```

### Что происходит с ответами

| Ответ | Действие |
|-------|----------|
| ✅ Ready/Будем | Ничего, урок идёт по плану |
| ⏰ Late/Опоздаем | Coordinator получает: «⏰ Родитель/Репетитор опоздает» |
| ❌ No-show/Не придём | Coordinator получает: «❌ Занятия не будет» |
| 🛠 Tech | Coordinator получает: «🛠 Проблема с платформой» |
| Нет ответа | Coordinator получает: «⚠️ Родитель/Репетитор не ответил до начала урока» |

## 7. Tutor start check

В момент начала урока репетитор получает:

```
▶️ Время урока по классу C9.
Ученики: Алиса Джонс

Отметьте статус старта урока.

[✅ Урок начался] [👤 Ученик не пришёл] [🛠 Техпроблема]
```

### Что происходит

| Кнопка | Действие |
|--------|----------|
| ✅ Урок начался | Ничего, всё ок |
| 👤 Ученик не пришёл | **Автоматически** запускается absence flow → parent получает уведомление |
| 🛠 Техпроблема | Coordinator получает алерт |

> ⚠️ Если репетитор пишет текстом вместо нажатия кнопки — текст передаётся координатору для ручной обработки (без автоматического absent).

## 8. Class not live detection

Если к `T + ALBION_CLASS_LIVE_GRACE_MIN` (5 мин) урок не перешёл в live (`classStatus=lv` не пришёл):

### Умные сообщения в зависимости от контекста

| Ситуация | Сообщение координатору |
|----------|----------------------|
| Tutor подтвердил готовность | ⚠️ Урок не в live, но репетитор подтвердил готовность → техпроблема / ученик не подключился |
| Tutor отметил отсутствие ученика | ℹ️ Урок не в live: репетитор уже отметил отсутствие → уведомление родителю отправлено |
| Tutor сообщил о техпроблеме | 🛠 Урок не в live: техпроблема у репетитора |
| Tutor не ответил | 🚨 Урок не в live, репетитор не ответил → возможные причины перечислены |

## 10. MeritHub интеграция

### Подключение

1. Получить credentials: Admin Console → API → Client ID + Secret
2. Вписать в `.env`:
   ```
   MERITHUB_CLIENT_ID=...
   MERITHUB_CLIENT_SECRET=...
   ```
3. Перезапустить бота — автоматически переключится на реальный API

### Импорт реальных данных из MeritHub

**Шаг 1: Импорт учеников**
```
1. Откройте MeritHub → Users → Learners
2. Скопируйте всю таблицу (Ctrl+A → Ctrl+C)
3. Отправьте как сообщение боту
4. Ответьте на это сообщение: /import_learners
```
Загружает: UserId, Name, Email, Country, Timezone.

**Шаг 2: Импорт привязок родитель→ученик**
```
1. Откройте MeritHub → Learner's customers
2. Скопируйте таблицу
3. Отправьте боту
4. Ответьте: /import_customers
```
Загружает: CustomerName, CustomerEmail, CustomerPhone, Country, City.

**Шаг 3: Привязка Telegram (вручную)**
```
/mh_user <LearnerId> <parentTG> <имя>
/mh_contact <LearnerId> tg <parentTG>
```

**Шаг 4: Проверка**
```
/mh_students     → ученики + timezone + parent contacts
/mh_contacts     → все контакты
/today           → обзор системы
```

### Создание занятий

Все занятия создаются в зоне **организации** — настройка `ALBION_ORG_TIMEZONE`
(по умолчанию **Europe/London**, британское время, как просит клиент).
Это осознанное продуктовое решение: зона репетитора для создания класса НЕ
используется — иначе классы одного оператора создавались бы по разным
конвенциям, а чужие DST-правила «плавали» бы по году. Зоны учеников и
репетиторов влияют только на отображение:
```
🕐 15:00 (London) / 20:00 (ваше время, Asia/Almaty) [+4ч к London]
```
Суффикс `[+Nч к London]` — реальная разница часовых поясов на дату занятия
(летом Almaty опережает London на 4ч, зимой на 5ч).

**Время без таймзоны** (например `2026-07-28T15:00:00`) трактуется в зоне
организации (`ALBION_ORG_TIMEZONE`), а не UTC — иначе напоминания уезжали бы
на час летом (BST). Лучше всегда передавать полный RFC3339 со смещением.

### Webhook setup

```bash
# Терминал 1: бот
python -m src.main

# Терминал 2: webhook receiver
uvicorn src.api.webhook:app --host 0.0.0.0 --port 8000

# Терминал 3: туннель
cloudflared tunnel --url http://localhost:8000
```

Полученный URL + `/merithub/webhook` → в MeritHub Admin Console → Webhook Url.

### Включить чекбоксы в MeritHub
- ✅ Attendance (главное — авто-неявки)
- ✅ Session Status (class not live detection)
- ☐ Остальное — опционально

### /mh_events — последние webhook'и

```
🛰 Последние события MeritHub:

✅ #3 [2026-07-28 15:30] type=attendance
headers: {"content-type": "application/json"}
raw: {"requestType": "attendance", "classId": "C9", ...}
```

### Как работает авто-неявка по webhook

```
MeritHub → attendance webhook → ALBION:
  зачисленные в класс (merithub_enrollments)
  минус присутствовавшие (totalTime > 0)
  = отсутствующие
  → trigger_absence для каждого → parent notification
```

## 13. Полный прогон демо (пошагово)

### Подготовка (5 мин)

```bash
# 1. Запустить бота
python -m src.main

# 2. Открыть бота в Telegram → /start → выбрать роль "координатор"

# 3. Узнать свой TG ID
/whoami    → TG ID: 111222333

# 4. Прописать себя как админа в .env
ALBION_ADMIN_TELEGRAM_IDS=111222333

# 5. Перезапустить бота

# 6. Для демо: короткие тайминги в .env
ALBION_NOTIFY_PARENT_DELAY_MIN=1
ALBION_ESCALATE_DELAY_MIN=2
ALBION_SCHEDULER_INTERVAL_SEC=5
```

### Прогон без MeritHub (10 мин)

```
# 1. Проверка
/pilot_seed
→ ✅ Пилот готов (если роли назначены)

# 2. Назначить роли (если 2-й аккаунт играет parent)
/role <PARENT_TG> parent
/role <COORD_TG> coordinator
```

## 15. Troubleshooting

| Проблема | Решение |
|----------|---------|
| Бот не отвечает | Проверить `TELEGRAM_BOT_TOKEN`. Запущен ли `python -m src.main`? |
| `/role` → «⛔ Только владелец» | Вписать свой TG ID в `ALBION_ADMIN_TELEGRAM_IDS`, перезапустить |
| Parent не получил уведомление | Parent написал `/start`? Роль `parent`? Kill Switch = 2? |
| Scheduler не тикает | `/status` → «Ожидает: N задач». `ALBION_SCHEDULER_INTERVAL_SEC` |
| Кнопка не работает | `/ok <ID>` — запасной способ. Проверить `/incidents` |
| MeritHub webhook не приходит | `/mh_events` пустой? Туннель поднят? URL в MeritHub правильный? |
| Нужно начать заново | `/demo_reset` |
| Бот потерял данные после рестарта | Не должен — SQLite персистентен. Проверить `albion.db` |
| AI не понимает текст | Без `OPENROUTER_API_KEY` работает эвристика. Для точности — добавить ключ |

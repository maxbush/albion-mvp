# AGENTS.md — правила для LLM-агентов в репозитории ALBION

Этот файл читает любой агент (Claude Code, Codex, Devin, Cursor…) до начала работы.

## 0. Порядок чтения
1. Этот файл.
2. `docs/phase1/ARCHITECTURE.md` — контракты и слои (это закон).
3. `docs/phase1/DECISIONS_NEEDED.md` — бизнес-правила и дефолты.
4. Карточку своей задачи в `docs/phase1/BACKLOG.md` (раздел `Txx`).
5. **Только** файлы из поля «Прочитать» карточки. Остальной код читать по
   необходимости через `grep`, а не целиком: `bot/handlers.py` (1500 строк),
   `bot/wizard.py` (1300) и `bot/pilot.py` (1400) целиком не открывать.

## 1. Жёсткие правила
- Одна задача = одна ветка/PR. Не делать работу соседних задач «заодно».
- Дифф ≤ ~400 строк без учёта тестов. Если выходит больше — остановиться и
  предложить разбиение в PR.
- Менять только файлы из поля «Можно менять» карточки (+ тесты, + `docs/`).
  Нужен другой файл — написать почему в описании PR.
- Все тесты зелёные: `python -m pytest -q`. Удалять или ослаблять
  существующий тест запрещено. Если тест проверял удалённое поведение — удалить
  тест можно только вместе с поведением и с пояснением в PR.
- Архитектурные тесты (`tests/arch/`) не редактировать, **кроме** уменьшения
  чисел в `tests/arch/baseline.json`. Увеличивать их нельзя.
- Бизнес-правила не придумывать. Нет в `DECISIONS_NEEDED.md` → сделать
  настройку с дефолтом и записать вопрос в PR.
- Внешние сервисы (Telegram, WhatsApp, MeritHub, LLM) в тестах — только через
  fake/mock. Сетевые вызовы в тестах запрещены.
- Время — только через `src/core/clock.py` (после T01). Время в БД — UTC.
- Пользовательские тексты — только в каталоге сообщений (после T09), всегда ru + en.
- SQL — только в `src/db/`. Только переносимый SQL (см. ARCHITECTURE §4.2).
- Секреты и персональные данные не писать в код, тесты, логи и фикстуры.
  Телефоны в тестах — только `+44 7700 900xxx` (диапазон Ofcom для драмы/тестов).
- Новые зависимости — только перечисленные в карточке.

## 2. Definition of Done (для каждой задачи)
- [ ] Все пункты «Приёмка» из карточки выполнены, тесты с указанными именами есть и проходят.
- [ ] `python -m pytest -q` зелёный; `ruff check src tests` без новых ошибок (после T00).
- [ ] `tests/arch/baseline.json` не вырос.
- [ ] Новые настройки есть в `src/config.py` и `.env.example` (с комментарием).
- [ ] Новые таблицы и колонки — через миграцию (после T05 — Alembic).
- [ ] Описание PR заполнено по шаблону ниже.

## 3. Шаблон описания PR
```
Задача: Txx — <название>
Что сделано: <3–7 пунктов>
Контракты: <какие сигнатуры из ARCHITECTURE реализованы/изменены>
Тесты: <новые тесты>; итого N passed
Baseline: <что уменьшилось в tests/arch/baseline.json>
Вопросы владельцу: <решения, принятые по дефолту>
Вне объёма / следующие шаги: <...>
```

## 4. Когда остановиться и спросить
- Контракт из ARCHITECTURE не подходит к реальному коду.
- Нужна правка больше чем в 2 файлах вне «Можно менять».
- Поведение, которое проверяет существующий тест, противоречит задаче.
- Нужна реальная учётка или секрет (Meta, MeritHub, VPS).

## 5. Команды
```
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q                      # все тесты (SQLite)
python -m pytest -q tests/arch           # границы слоёв
ALBION_TEST_DATABASE_URL=postgresql+asyncpg://albion:albion@localhost:5432/albion_test \
  python -m pytest -q -m "not sqlite_only"   # прогон на Postgres (после T05)
```

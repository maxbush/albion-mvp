## 1. Что такое ALBION

**ALBION — координатор репетиторских уроков в Telegram.**

Он следит за каждым занятием и сам общается с участниками: напоминает,
спрашивает, фиксирует, эскалирует. НИКАКИХ отдельных приложений и сайтов —
весь интерфейс живёт в Telegram, где уже сидят ваши родители, ученики и
репетиторы.

**Для кого:** владельцы и координаторы репетиторских компаний, у которых
расписание и ученики — в MeritHub (или похожей системе).

**Что закрывает пилот:**

| Боль бизнеса | Решение ALBION |
|---|---|
| Ученик не пришёл — узнаём постфактум | Система замечает неявку сама и за минуты выясняет причину у родителя |
| Координатор тонет в рутинных обзвонах | Координатор подключается **только по исключению** — когда система не справилась |
| Репетитор забыл отменить/перенести урок | Одна команда — и все стороны мгновенно уведомлены с причиной |
| «А шёл ли вообще урок?» | Контроль старта: репетитор подтверждает начало, иначе алерт за 5 минут |
| Хаос часовых поясов (UTC, Лондон, Алматы) | Каноническая зона расписания + каждый видит время в своём поясе |

## 2. Ключевая идея: Management by Exception

Обычная автоматизация присылает координатору **всё**. ALBION присылает
координатору **только то, что требует человека**.

```
Ученика нет на уроке
        │
        ▼
ALBION спрашивает родителя (кнопки или свободный текст)
        │
        ├─ Родитель ответил → ситуация закрыта, координатор получает
        │   короткий информационный апдейт (действий не требуется)
        │
        └─ Родитель молчит N минут → ЭСКАЛАЦИЯ: координатор получает
            карточку с полным контекстом + кнопки действия
```

> 💬 **Фраза для презентации:** «Из четырёх типовых ситуаций три решает сам
> родитель одной кнопкой. До человека доходит только одна — и та закрывается
> в один тап.» *(цифра из нашего демо-прогона, см. раздел 13)*

## 3. Как выглядит сценарий неявки (главный кейс)

Шаг за шагом — с реальными сообщениями системы *(полная автоматически
сгенерированная расшифровка — в файле `DEMO_TRANSCRIPT.md`, она обновляется
одной командой перед каждым демо)*.

**Шаг 0.** Ученик отсутствует на уроке. Система узнаёт об этом одним из
трёх способов: webhook посещаемости из MeritHub, кнопка репетитора
«👤 Ученик не пришёл» при старте урока, или команда `/pilot_absent` (в демо).

**Шаг 1. Родителю уходит вопрос** (через ~1–5 мин, настраивается):

> 👋 Здравствуйте!
>
> Алиса отсутствовал(а) на занятии (C9, 28.07, 15:00).
> Подскажите, пожалуйста, что верно — ответьте кнопкой ниже или просто текстом.
>
> кнопки: [✅ Всё в порядке] [❌ Сегодня не будет] [⏰ Опоздаем]

**Шаг 2. Три возможных финала:**

| Финал | Что происходит |
|---|---|
| ✅ Родитель ответил кнопкой | Инцидент закрыт мгновенно. Сообщение превращается в «Отметили: Алиса · ситуация закрыта». Координатор получает короткий апдейт с исходом. |
| 💬 Родитель написал текстом | «Мы опоздаем на 15 минут — пробки» → система понимает смысл (опоздание), закрывает ситуацию, а координатору уходит апдейт **с исходным текстом родителя**. |
| 🚨 Родитель молчит | Через заданное время — эскалация всем координаторам: ученик, занятие, TG родителя, время создания + кнопки **[✅ Закрыть ситуацию]** и **[👤 Написать родителю]** (прямой переход в чат. |

> 💬 **Фраза для презентации:** «Родитель не учит команды — пишет как привык.
> Система понимает. А координатор видит не «инцидент #4482», а готовую
> карточку со всем, что нужно для звонка.»

## 4. Роли в системе

| Роль | Кто это | Что делает в ALBION |
|---|---|---|
| 👑 **Владелец (админ)** | Вы и ваши партнёры | Управляет ролями, запускает/гасит систему, смотрит метрики. Админство = TG ID в настройках, а не роль в базе |
| 👨‍💼 **Координатор** | Сотрудник, отвечающий за уроки | Получает эскалации и апдейты, закрывает ситуации в один тап, смотрит расписание дня |
| 🧑‍🏫 **Репетитор** | Преподаватель | Подтверждает готовность к уроку и старт урока кнопками, отменяет урок командой |
| 👨‍👩‍👦 **Родитель** | Клиент | Отвечает на вопросы о ребёнке — кнопкой или обычным текстом |
| 🎓 **Ученик** | Старшеклассник (опционально) | Получает напоминания о занятиях |

**Меню «/» подстраивается под роль:** родитель видит 5 команд, репетитор —
5, координатор — 12 (включая пошаговые визарды создания занятия, ученика и
репетитора). Никто не видит лишнего, никого не пугают админские функции.
Незнакомцу бот сначала предлагает выбрать роль — никаких «тихих» регистраций.
Репетиторы — англоговорящие: все их карточки и кнопки на английском
(язык задаётся при регистрации, словарь RU/EN в паритете).

## 5. Первый запуск пилота — за 15 минут

**Подготовка (делается один раз техспециалистом):**

1. Развернуть бота из репозитория (`python -m src.main`), задать
   `TELEGRAM_BOT_TOKEN` в `.env`.
2. Вписать TG ID владельцев в `ALBION_ADMIN_TELEGRAM_IDS=` (узнать свой ID:
   написать боту `/start`, затем `/whoami`).
3. Опционально: ключи MeritHub (`MERITHUB_CLIENT_ID/SECRET`) — **без них
   система работает на mock-данных**, демо не пострадает.
4. Опционально: `OPENROUTER_API_KEY` для полноценного понимания свободного
   текста. Без ключа работает встроенная ключевая эвристика — для пилота
   достаточно.

**Раздача ролей (в чате с ботом, 3 минуты):**

```
/whoami                      → каждый участник узнаёт свой TG ID
/role 2001 coordinator       → владелец назначает координатора
/role 3001 parent            → …родителя
/role 4001 tutor             → …репетитора
/roles                       → проверка всего списка
/pilot_seed                  → «✅ Пилот готов»
```

**Создание данных — пошаговыми визардами (без заучивания синтаксиса):**
`/schedule` — занятие (разовое или 🔁 регулярное по дням недели),
`/add_student` — ученик + привязка родителя, `/add_tutor` — репетитор.
Визард ведёт кнопками и свободным текстом, на каждом шаге есть «назад».

**Проверка:** `/status` → `✅ ALBION · Роль · AI · Ожидает: N задач`.

## 6. День владельца с ALBION

| Утро | В течение дня | Вечер |
|---|---|---|
| Автосводка в 07:30 всем координаторам + `/today` — занятия дня: название курса, время, «до урока N мин», ученики, живой статус | Молчание = всё в порядке. Сообщения = апдейты или эскалации | `/incidents` — итоги дня одной строкой статистики; `/leads` — свежие заявки |

Для координатора то же самое + `/morning` (сводка по запросу), `/lessons`
(организационный обзор 7 дней со ссылками для пересылки родителям) и кнопки
действия прямо на эскалациях. Отдельный вход в «систему» не нужен — рабочее
место координатора это обычный чат с ботом.

## 7. Что автоматизировано (карта процессов)

| Процесс | Что делает система сама | Где нужен человек |
|---|---|---|
| **Неявка ученика** | Обнаружение (webhook MeritHub / кнопка репетитора), опрос родителя, закрытие по ответу, эскалация при молчании | Только эскалации |
| **Напоминания до урока** | За N минут до урока родителю и репетитору — карточка с кнопками «Будем/Опоздаем/Не придём», у репетитора — на английском | Если кто-то не ответил к началу — апдейт координатору с кнопкой «Написать…» |
| **Старт урока** | В момент начала репетитору: «Урок начался / Ученик не пришёл / Техпроблема» | «Ученик не пришёл» автоматически запускает сценарий неявки |
| **Урок не начался** | Нет статуса live через 5 мин после старта → алерт координатору с контекстом, кто именно молчит | Звонок репетитору |
| **Отмена урока** | Одна команда (или кнопка из списка занятий) → репетитор и координаторы уведомлены с причиной | — |
| **Отмена свободным текстом** | «Отмени урок» → бот предлагает кнопки с реальными ближайшими занятиями | Выбор занятия |
| **Сообщение о неявке текстом** | «Дочь сегодня не сможет» из ниоткуда → пересылается координаторам с TG автора, автор получает подтверждение | Разбор вручную |
| **Регулярное расписание** | Занятия «каждую ср/пт» создаются один раз как серия 🔁; дайджест, `/today` и `/lessons` разворачивают её в реальные даты сами | Правка/перенос серии — через визард |
| **Утренняя сводка** | Каждый день 07:30 (зона организации) всем координаторам: занятия дня, ученики, репетиторы, открытые инциденты | — |
| **Захват лидов** | «Хочу пробное занятие» от незнакомца → извлечение имени/условий, карточка заявки координаторам, автору — вежливое подтверждение | Обзор картоти: `/leads`; звонок клиенту |
| **Непонятные сообщения** | Вопрос/прочее → честный ответ пользователю + алерт координаторам с кнопкой перехода в чат с автором | Ответ человеком |

## 8. MeritHub-интеграция (модель «import & observe»)

ALBION **не заменяет** MeritHub — он надстраивает его коммуникацией.

**Честно про возможности вендора:** MeritHub умеет **создавать** классы,
пользователей и зачисления через API, а дальше присылает события
webhook'ами. Методов «прочитать занятие» или «отменить урок» у вендора
нет — их нет и у нас (mock-провайдер сознательно повторяет реальный
интерфейс один в один, этот паритет проверяется тестом). Поэтому рабочая
модель: **создаём через API → расписание храним у себя → наблюдаем за
событиями.**

| Возможность | Как работает |
|---|---|
| Импорт учеников | `/import_learners` — вставляете таблицу из MeritHub, ученики загружаются с часовыми поясами |
| Импорт контактов родителей | `/import_customers` — email/телефон/город привязываются к ученикам |
| Привязка Telegram к ученику | `/mh_user <ID> <TG> Имя` — одна команда на ученика |
| Репетиторы | `/mh_tutor t01 <TG> Имя` |
| Занятия | Визард `/schedule` (разовое или 🔁 серия по дням) — создание в MeritHub, выдача ссылок репетитору и родителям, зачисление, постановка контроля урока. Legacy-команда `/mh_schedule` делает то же самое одной строкой (для опытных) |
| Наполнение для демо | `/seed10 <TG1> <TG2>` — 10 учеников и 3 репетитора одной командой |
| Авто-неявки | Webhook `attendance` после урока → для каждого отсутствовавшего стартует опрос родителя |
| Контроль live | Webhook `classStatus` (`lv` = урок идёт, `cp` = завершён) + проверка через 5 мин после старта; события старт/финал пишутся для будущей аналитики |
| Диагностика | `/mh_events` — последние webhook'и, `/mh_students` — привязки |

> 💬 **Честный ответ на вопрос «умеет ли MeritHub сообщать о неявке»:**
> напрямую в реальном времени — нет. ALBION покрывает это тремя способами:
> attendance-webhook после урока, кнопка репетитора при старте и контроль
> перехода урока в live.

**Без ключей MeritHub** всё вышеперечисленное работает на встроенных
mock-данных — этого достаточно для пилота и демонстраций. Webhook'и вендор
подписывать пока не начал: приёмник принимает их без подписи, проверка
включается одной переменной окружения, когда подпись появится.

## 9. Часовые пояса — без сюрпризов

- **Каноническая зона расписания** задаётся одной настройкой
  `ALBION_ORG_TIMEZONE` (по умолчанию `Europe/London`). Все занятия
  создаются и хранятся в ней — это единственный источник правды.
- **Зоны учеников** импортируются из MeritHub и служат **только для
  отображения**: каждый участник видит время в своём поясе.
- Двойной формат в уведомлениях: `15:00 London [+4ч]` — видно и локальное
  время, и смещение от канонического. Смещение считается реально, с учётом
  летнего/зимнего времени.

| `ALBION_DEMO_MODE` | Тестовые пользователи при старте | `false` | `true` локально |
| `OPENROUTER_API_KEY` | Полноценный AI для свободного текста | пусто (эвристика) | по желанию |

запланированные уведомления не теряются. Полный список переменных —
`.env.example` (тест гарантирует, что пример не отстаёт от кода).

## 11. Kill Switch — аварийный рубильник

Команда `/kill_switch` (только владельцам) выводит три кнопки:

| Уровень | Значение | Когда использовать |
|---|---|---|
| 🔴 ВСЁ ВЫКЛ | Никому ничего не отправляется | Что-то пошло не так, разбираемся |
| 🟡 Только координаторам | Родители/репетиторы не получают сообщений, координаторы — получают | Мягкая отладка на живых данных |
| 🟢 Полностью | Штатный режим | Боевая работа |

Текущий уровень всегда виден в `/status`.

## 12. Надёжность MVP (что под капотом, одним слайдом)

- **Переживает рестарт:** все отложенные задачи в SQLite (WAL-режим) — после
  перезапуска напоминания и эскалации выполнятся.
- **Не спамит:** повторное нажатие кнопки не переоткрывает ситуацию
  (idempotency-nonce); просроченные check-in'ы игнорируются; повторный
  прогон зависшей задачи не дублирует сообщение родителю и вторую эскалацию.
- **Не теряет:** отправка с 3 повторами; отложенные задачи без обработчика
  уходят в журнал ошибок (DLQ), а не исчезают молча; «зомби»-задачи
  (упавшие с lock'ом) возвращаются в очередь.
- **Быстро:** карточки расписания собираются пакетными запросами
  (оптимизация R7: 6 циклов «запрос-на-строчку» заменены на 6 пакетов).
- **Честно:** если урок не найден — бот так и скажет, а не сымитирует успех;
  если не понял сообщение — признаётся и зовёт координатора.

## 13. Как показать систему клиенту за 15 минут

1. **Перед встречей** обновить расшифровку демо:
   `python scripts/demo_dry_run.py --out DEMO_TRANSCRIPT.md` — прогоняет
   реальные workflow без Telegram и печатает все сообщения (используйте её
   для скриншотов и репетиции).
2. **Живой показ** — по пошаговому сценарию `DEMO_RUNBOOK.md`:
   3–4 телефона (владелец, координатор, родитель) + ускоренные тайминги
   из раздела 10.
3. **Обязательные wow-моменты:** кнопка «Всё в порядке» → мгновенное
   закрытие; свободный текст родителя → апдейт с исходным текстом;
   молчание → эскалация с кнопками; финалом `/incidents`.

> 💬 **Закрывающая фраза встречи:** «Это боль №1 — неявки. Дальше по той же
> рельсе: расписания, оплаты, лиды».

|---|---|
| Координатор может назначить себя сам (без подтверждения админа) | **Отложено сознательно** — для удобства тестирования; перед боем включаем заявочную модель (кандидат: флаг `ENABLE_ADMIN_APPROVAL`) |
| Webhook MeritHub принимается без проверки подписи | MeritHub сейчас не подписывает пинги; проверка включается одной настройкой, когда появится |
| Понимание свободного текста без API-ключа — на ключевых словах RU/EN | Для пилота достаточно; перед демо клиенту подключить ключ OpenRouter (одна строка в .env) |
| Перенос отдельного занятия внутри регулярной серии | Серии работают как паттерн дней; поправку «только эту ср» включаем следующим этапом (проект уже заложен, решение владельца H2) |
| Поиск workflow идёт по JSON-тексту (SQLite LIKE) | Ограничение MVP; при росте данных — перейти на json_extract/индексы |
| Учёт оплат (баланс) | Выключен решением владельца до интеграции с Xero (события оплат удалены из кода, чтобы не висеть фантомами) |
| Одна организация на инстанс, SQLite-файл | Лимиты MVP; мульти-тенантность и Postgres — следующий масштаб (слой данных уже изолирован под миграцию) |

## 15. Дорожная карта после пилота

1. **Сейчас (пилот):** неявки, напоминания, контроль старта, отмены, роли,
   метрики, регулярные серии, авто-сводка, захват лидов + `/leads`.

   событий старт/финал урока в аналитику.
3. **Затем:** подтверждение занятий, авто-переносы; оплаты и баланс

4. **Далее:** WhatsApp-мост для родителей (ограничения Business API уже

   тарификация), авто-онбординг новых клиентов из лидов.

Каждый следующий этап использует ту же платформу: события → workflow →
уведомления в Telegram → эскалация по исключению. Задокументировано (

## 17. Если что-то пошло не так

| Симптом | Первое действие |
|---|---|
| Родитель не получил уведомление | `/status` → Kill Switch должен быть 🟢. Родитель писал боту `/start`? Роль `parent` назначена? |
| Ничего не тикает | `/status` → «Ожидает: N задач». Уменьшить `ALBION_SCHEDULER_INTERVAL_SEC` |
| Кнопка «висит» | Запасной вариант: `/ok <ID ситуации>` |
| Нужен чистый прогон | `/demo_reset` → подтвердить кнопкой (покажет, что именно будет очищено) |
| MeritHub отвечает ошибками | `/mh_events` — смотрим payload. Система продолжает работать на mock-данных |
| Бот «умер» | Перезапустить `python -m src.main` — база и расписание переживут рестарт |

## 18. Глоссарий (для презентации)

- **Инцидент / ситуация** — событие «ученика не было на уроке», у которого
  есть жизненный цикл: создан → опрашиваем → закрыт или эскалирован.
- **Эскалация** — передача ситуации человеку, когда автоматика исчерпала себя.
- **Workflow** — сценарий системы (например, «уведомить родителя → подождать →
  эскалировать»), хранится в базе и переживает рестарт.
- **Kill Switch** — глобальный рубильник отправки сообщений.
- **Mock-режим** — работа на встроенных демо-данных вместо реального MeritHub.
- **Management by Exception** — принцип: человек занимается только
  исключениями, рутину закрывает система.
- **Серия (🔁 perma)** — регулярное занятие, хранится паттерном дней недели
  («ср+пт») и разворачивается в реальные даты при каждом показе.
- **Import & observe** — модель интеграции с MeritHub: создаём через API,
  дальше живём по webhook-событиям (create-only вендор).
- **Каноническая зона** — единый часовой пояс расписания организации
  (`ALBION_ORG_TIMEZONE`); зоны участников — только для отображения.

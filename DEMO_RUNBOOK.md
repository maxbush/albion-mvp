# 🎬 ALBION Demo Runbook

> Пошаговый сценарий демонстрации MVP клиенту.
> Время: 15–20 минут. Аккаунты: 3–4 TG (admin, coordinator, parent ×1–2).

---

## 🧭 Общая структура демо

```
Часть 1. Подготовка (5 мин)       — seed данных, проверка
Часть 2. Сценарий неявки (5 мин)  — кнопка + free text + escalation
Часть 3. Pre-lesson reminders     — напоминания за 15 мин до урока
Часть 4. MeritHub интеграция       — авто-неявки по webhook (если подключён)
Часть 5. Координатор              — incidents, today, outcome notifications
```

---

## 📋 Подготовка

### Аккаунты

| Роль | Кто играет | Команда |
|------|-----------|---------|
| `admin` + `tutor` | Вы | `/role <ВАШ_TG> tutor` |
| `coordinator` | Owner #1 или второй ваш аккаунт | `/role <TG> coordinator` |
| `parent` | Owner #2 | `/role <TG> parent` |

### Переменные окружения (для живого демо)

```dotenv
ALBION_NOTIFY_PARENT_DELAY_MIN=1
ALBION_ESCALATE_DELAY_MIN=2
ALBION_SCHEDULER_INTERVAL_SEC=5
ALBION_PRELESSON_REMINDER_MIN=15
ALBION_CLASS_LIVE_GRACE_MIN=5
```

### Предполётная проверка

```
/pilot_seed       → ✅ Пилот готов
/status           → AI, Kill Switch, БД
```

## 🎬 Часть 2: Сценарий неявки (главная боль клиента)

### 2a. Кнопка «Всё в порядке» (счастливый путь)

```
/pilot_absent
```

**Что показать:**
1. Parent получает уведомление с 3 кнопками
2. Parent нажимает «✅ Всё в порядке»
3. Инцидент закрывается мгновенно
4. Coordinator НЕ отвлекается (management by exception)

**Ключевая фраза:** *"Координатор не тратит ни секунды — система сама разобралась."*

### 2b. Кнопка «Опоздаем»

```
/demo_reset
/pilot_absent
```

**Что показать:**
1. Parent нажимает «⏰ Опоздаем»
2. Coordinator получает: `⏰ Родитель сообщил: ученик опоздает`
3. Инцидент закрыт, координатор в курсе

### 2c. Свободный текст (AI-интерпретация)

```
/demo_reset
/pilot_absent
```

**Что показать:**
1. Parent получает уведомление
2. Вместо кнопки пишет текстом: *"Мы задержимся на 15 минут, пробки"*
3. AI понимает → `late`
4. Parent получает: `⏰ Спасибо! Отметили, что ученик опоздает.`
5. Coordinator получает уведомление с исходным текстом

**Ключевая фраза:** *"Родитель не учит команды — пишет как привык. Система понимает."*

### 2d. Нет ответа → эскалация

```
/demo_reset
/pilot_absent
# НЕ нажимайте ничего, ждите ALBION_ESCALATE_DELAY_MIN
```

**Что показать:**
1. Parent молчит
2. Через 2 минуты coordinator получает: `🚨 Эскалация: инцидент #N`
3. Coordinator разбирает вручную

**Ключевая фраза:** *"Координатор подключается ТОЛЬКО когда система не справилась сама."*

## 🎬 Часть 3: Pre-lesson reminders (профилактика)

> Требует реальный MeritHub класс с будущим временем старта.
> Для демо: поставьте start_time через 2 минуты.

```
# Создаём занятие с ближайшим стартом
/mh_schedule t02 2026-07-28T15:02:00+03:00 60 s01

# Ждём 15 минут (или уменьшите ALBION_PRELESSON_REMINDER_MIN=1)
```

**Что показать:**

1. **Parent** получает за N мин до урока:
   > ⏰ Напоминание: через 15 мин занятие.
   > Ученик: Алиса Джонс
   > Репетитор: Иван Сидоров
   >
   > [✅ Будем] [⏰ Опоздаем] [❌ Не придём]

2. **Tutor** получает:
   > 🧑‍🏫 Через 15 мин урок.
   > Репетитор: Иван Сидоров
   > Ученики: Алиса Джонс
   >
   > [✅ Готов(а)] [⏰ Опоздаю] [❌ Не смогу] [🛠 Проблема]

3. Если parent/tutor не ответил к началу урока:
   > ⚠️ Родитель не ответил до начала урока
   > ⚠️ Репетитор не подтвердил готовность

4. **Tutor start check** (в момент начала урока):
   > ▶️ Время урока по классу C9.
   > Ученики: Алиса Джонс
   >
   > [✅ Урок начался] [👤 Ученик не пришёл] [🛠 Техпроблема]

5. Если tutor нажимает «👤 Ученик не пришёл» → **автоматически** запускается absence flow → parent получает уведомление!

**Ключевая фраза:** *"Мы не ждём, пока проблема случится — мы предотвращаем."*

## 🎬 Часть 4: MeritHub интеграция

### 4a. Авто-неявки по attendance webhook

Когда MeritHub после окончания урока шлёт `requestType=attendance`, система:
1. Сравнивает зачисленных с присутствовавшими
2. Для каждого отсутствующего → `trigger_absence` → уведомление parent

```
# После реального урока в MeritHub:
/mh_events      → увидеть webhook payload
/incidents      → увидеть созданные инциденты
```

### 4b. Class not live detection

Если урок должен был начаться, но `classStatus=lv` не пришёл к `T+5min`:
> 🚨 Урок не перешёл в live вовремя
> Класс: C9
> Репетитор: Иван Сидоров

```
/mh_events      → увидеть classStatus webhook
```

### Про вопрос клиента: "может ли MeritHub уведомлять о неявке ученика?"

**Ответ:** Да, но с нюансами:

| Способ | Когда | Автоматичность |
|--------|-------|---------------|
| `attendance` webhook | После окончания урока | ✅ Полностью |
| `tutor_start_check` кнопка | В момент начала урока | ✅ Одна кнопка от tutor |
| `classStatus` не пришёл | T+5min после старта | ✅ Автоматический alert |

MeritHub **не шлёт** "ученик не подключился в реальном времени". Но мы покрываем это 3 способами выше.

## 🛡 Если что-то пошло не так

| Проблема | Решение |
|----------|---------|
| Parent не получил уведомление | `/status` → Kill Switch = 2. Parent написал `/start`? |
| Scheduler не тикает | Проверить `ALBION_SCHEDULER_INTERVAL_SEC`. `/status` → «Ожидает: N задач» |
| Кнопка не работает | `/ok <ID>` — запасной способ закрыть инцидент |
| Нужно начать заново | `/demo_reset` |
| MeritHub API ошибка | `/mh_events` — посмотреть payload. Работает и без MeritHub |
| Бот не отвечает | Перезапустить `python -m src.main`. SQLite переживёт рестарт |

## 🎯 Порядок показа клиенту (рекомендуемый)

1. **Открыть `/today`** — показать систему в работе
2. **`/pilot_absent` → parent нажимает ✅** — 30 сек, wow-эффект
3. **`/demo_reset` → `/pilot_absent` → parent пишет текст** — AI понимает
4. **`/demo_reset` → `/pilot_absent` → parent молчит** — эскалация
5. **`/incidents`** — показать статистику
6. **(Если MeritHub подключён)** Показать `/mh_events` с реальными webhook'ами
7. **Закрыть фразой:** *"Это боль №1. Следующие: расписания, оплаты, лиды."*

## 📎 Шпаргалка команд

```
# Подготовка
/whoami               → узнать свой TG ID
/role <TG> <роль>     → назначить роль
/roles                → список всех
/pilot_seed           → проверка готовности
/seed10 <TG1> <TG2>   → 10 учеников + 3 репетитора

# Демо неявки
/pilot_absent         → запустить сценарий
/demo_reset           → сброс между прогонами
/ok <ID>              → закрыть инцидент вручную

# MeritHub
/mh_tutor t01 <TG> Анна          → создать репетитора + TG
/mh_user s01 <parentTG> Алиса     → создать ученика
/mh_schedule t01 <start> 60 s01   → создать занятие + зачислить
/mh_students                        → список учеников
/mh_events                          → последние webhook'и

# Мониторинг
/status               → состояние системы
/incidents            → инциденты
/today                → обзор на сегодня
/kill_switch 0|1|2    → управление отправкой
```
